## 🎯 痛点与愿景

### 问题 1：AI 的"失忆症"

**问题描述**：

```
┌─────────────────────────────────────────────────────────────┐
│  传统 AI 协作模式                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第 1 轮：用户说"项目用 Python 3.11"                         │
│     ↓                                                       │
│  第 10 轮：AI 问"你的 Python 版本是多少？"  ← 忘记了！       │
│     ↓                                                       │
│  第 15 轮：用户重复"是 3.11"                                 │
│     ↓                                                       │
│  第 20 轮：AI 又问"Python 版本？"           ← 又忘了！       │
│                                                             │
│  结果：用户反复回答相同问题                                   │
└─────────────────────────────────────────────────────────────┘
```

**Evolution 的解决方案**：

```
┌─────────────────────────────────────────────────────────────┐
│  Evolution 协作模式                                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第 1 轮：用户说"项目用 Python 3.11"                         │
│     ↓                                                       │
│  [后台] Sub-agent 记录到 facts.md                            │
│     ↓                                                       │
│  第 10 轮：AI 读取 facts.md，知道是 3.11                     │
│     ↓                                                       │
│  第 15 轮：AI 继续正确使用 3.11                              │
│                                                             │
│  结果：AI 记住关键信息，用户无需重复                          │
└─────────────────────────────────────────────────────────────┘
```

## 🧠 核心原理

### 原理 1：索引 + 详情文件架构

```
┌─────────────────────────────────────────────────────────────┐
│                       知识库架构                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────┐                                        │
│  │   kb-index.md   │  ← 按需读取（不自动加载）              │
│  │                 │                                        │
│  │  概览           │  ← 告诉 AI 有哪些信息可用              │
│  │  摘要           │  ← 引导 AI 按需加载详情                │
│  └─────────────────┘                                        │
│           │                                                 │
│           ↓ 按需加载                                        │
│                                                             │
│  ┌─────────────────┐  ┌─────────────────┐                  │
│  │    facts.md     │  │  pitfalls.md    │  ← 详情文件      │
│  │                 │  │                 │                  │
│  │  • 环境配置     │  │  • 错误模式     │                  │
│  │  • 技术决策     │  │  • 解决方案     │                  │
│  │  • 依赖关系     │  │  • 注意事项     │                  │
│  └─────────────────┘  └─────────────────┘                  │
│                                                             │
│  优势：                                                     │
│  ✅ 索引小（<200 行），快速加载                             │
│  ✅ 详情按需加载，节省 token                                │
│  ✅ 结构清晰，易于维护                                      │
└─────────────────────────────────────────────────────────────┘
```

### 原理 2：增量写入 + 去重机制

```
┌─────────────────────────────────────────────────────────────┐
│                      数据写入策略                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第一次 /evolution                                          │
│     ↓                                                       │
│  facts.md:                                                  │
│  - [10:00] WSL 网络必须使用镜像模式                          │
│                                                             │
│  第二次 /evolution（2 小时后）                               │
│     ↓                                                       │
│  facts.md:                                                  │
│  - [10:00] WSL 网络必须使用镜像模式                          │
│    ← 更新时间戳，不新增条目                                  │
│  - [12:00] Python 版本必须是 3.11      ← 新增条目            │
│                                                             │
│  规则：                                                     │
│  ✅ 相同信息 → 更新时间戳                                    │
│  ✅ 新信息 → 追加写入                                        │
│  ✅ 状态更新 → 标记为"已完成"                                │
└─────────────────────────────────────────────────────────────┘
```

### 原理 3：人工审核（写入审核机制）

```
┌─────────────────────────────────────────────────────────────┐
│                    写入审核机制                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  每条新增条目都会带有状态标签：                              │
│                                                             │
│  [D] Draft     — AI 提取，尚未验证                          │
│  [V] Verified  — 用户确认或工具验证                         │
│  [X] Deprecated — 错误或已废弃                              │
│                                                             │
│  读取优先级：                                               │
│  1. [V] 条目可信任                                         │
│  2. [D] 条目可用但标记为"未验证"                            │
│  3. [X] 条目永不读取                                       │
│                                                             │
│  目标：防止 AI 错误自我强化                                  │
└─────────────────────────────────────────────────────────────┘
```

## 🤖 执行模型

> **所有 Evolution 操作都通过 sub-agent 运行，以减少主会话污染。**

### 工作原理

```
用户输入 /evolution
    ↓
┌─────────────────────────────────────────────────────────────┐
│  主 Agent（调度器）                                         │
│                                                             │
│  1. 接收用户命令                                            │
│  2. 在后台触发 sub-agent                                    │
│  3. sub-agent 完成后展示摘要                                │
│  4. 不直接操作知识库                                        │
└─────────────────────────┬───────────────────────────────────┘
                          │ 触发
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  Sub-Agent（后台工作者）                                    │
│                                                             │
│  1. 读取对话上下文                                          │
│  2. 提取知识                                                │
│  3. 写入知识库                                              │
│  4. 返回摘要给主 Agent                                      │
└─────────────────────────────────────────────────────────────┘
```

### 可用命令

| 命令 | 说明 |
|------|------|
| `/evolution` | 完整同步（全量知识提取） |
| `/evolution-init` | 初始同步 — 分析完整对话历史，从零构建知识库 |
| `/kb-sync` | 仅同步知识库 |
| `/growth-sync` | 仅生成学习笔记 |
| `/alignment-sync` | 仅检查对齐项 |

### 对话导出方式

**方式 A：AI 记忆（默认）**
- Sub-agent 分析当前会话的对话上下文
- 简单、实时、无需额外文件
- 仅限于当前会话

**方式 B：文件记录（可选）**
- Sub-agent 读取 `.claude/.tmp/conversation-*.md` 文件
- 持久化、可追溯、支持跨会话分析
- 需要对话导出文件

## 🔄 工作流程

### 完整流程

```
用户输入 /evolution
    ↓
主 Agent → Sub-Agent（后台）
    ↓
Sub-Agent:
  ├── 读取对话上下文
  ├── 读取 kb-index.md（了解已有知识）
  ├── 提取知识
  │   ├── 关键事实 → facts.md
  │   ├── 踩坑记录 → pitfalls.md
  │   ├── 状态变化 → state.md
  │   ├── 学习要点 → growth-notes.md
  │   ├── Prompt 改进 → prompt-improvements.md
  │   ├── 对齐项 → alignment.md
  │   └── 决策 → decisions.md
  ├── 与已有知识去重
  ├── 更新 kb-index.md
  └── 返回摘要
    ↓
主 Agent 展示摘要：
  "同步完成：+3 条事实，+1 条踩坑，+2 条状态更新"
```

### 信息流向

```
┌──────────────────────┐
│  对话上下文          │
│  （当前会话）        │
└──────────┬───────────┘
           │
           ↓
    ┌──────────────┐
    │  Sub-Agent   │
    │  （后台）    │
    └──────┬───────┘
           │
           ↓
┌──────────────────────────────────────────┐
│  知识库（8 个 .md 文件）                 │
│                                          │
│  facts.md  pitfalls.md  state.md         │
│  growth-notes.md  prompt-improvements.md │
│  alignment.md  decisions.md              │
└──────────────────────────────────────────┘
           │
           ↓
┌──────────────────────┐
│   kb-index.md        │
│   （已更新）         │
└──────────┬───────────┘
           │
           ↓
┌──────────────────────┐
│  AI 在下次对话中     │
│  读取索引            │
└──────────────────────┘
```

## 🚀 快速开始

### 1. 安装

**方式 A：从本仓库复制**

```bash
# 克隆仓库
git clone https://github.com/lemenlemen/evolution.git
cd evolution

# 复制 skill 和知识库到你的项目
cp -r .claude/skills/evolution/ <你的项目>/.claude/skills/
cp -r evolution/ <你的项目>/
```

**方式 B：直接下载 SKILL.md**

```bash
# 创建 skill 目录
mkdir -p .claude/skills/evolution

# 下载 SKILL.md
curl -o .claude/skills/evolution/SKILL.md \
  https://raw.githubusercontent.com/lemenlemen/evolution/main/.claude/skills/evolution/SKILL.md

# 创建 knowledge-base 目录和模板
mkdir -p evolution/knowledge-base
# （从仓库复制模板文件）
```

完整说明请参见 [安装指南](docs/INSTALLATION_GUIDE.md)。

### 2. 使用

在你的项目中打开 Claude Code，然后：

```bash
/evolution-init   # 首次：分析完整对话，构建知识库
/evolution        # 后续：增量同步
```

### 3. 查看结果

执行完成后，查看 `evolution/knowledge-base/` 目录：

- `kb-index.md` - 索引文件
- `facts.md` - 关键事实
- `pitfalls.md` - 踩坑记录
- `state.md` - 当前状态
- `growth-notes.md` - 学习笔记
- `alignment.md` - 对齐清单
- `decisions.md` - 决策记录

## 💡 设计理念

> **不要人为制造摩擦。首要目标是把任务完美完成，然后自然而然地把有意义的事情做了。**

Evolution 不是额外的负担，而是任务执行过程中的自然副产品。

### 核心原则

| 原则 | 说明 |
|------|------|
| **任务优先** | 首要目标是完成任务，不是运行系统 |
| **自然发生** | 学习和沉淀在任务执行中自然发生 |
| **Sub-agent 隔离** | 后台运行，不污染主对话 |
| **渐进成长** | AI 和人类都在协作中成长 |
| **诚实透明** | AI 如实汇报局限和问题 |
