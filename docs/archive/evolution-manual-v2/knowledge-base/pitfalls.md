## 错误模式

### 1. GitHub MCP 限制
- **问题**：GitHub MCP 没有批量上传功能，只能逐个文件上传
- **影响**：12 个文件需要 12 次 API 调用
- **解决**：使用 git 命令行推送（需要配置认证）

### 2. git push 超时
- **问题**：在中国大陆推送 GitHub 经常超时
- **解决**：配置本地代理后推送（代理地址属本地环境配置，不入库）

### 3. 敏感信息泄漏风险
- **问题**：facts.md 等文件包含本地路径、Webhook、Token 等敏感信息
- **影响**：上传到 GitHub 会泄露个人信息
- **解决**：
  - 只保留核心系统文件
  - 移除所有包含具体项目信息的文件
  - 使用模板代替实际数据

### 4. Release 创建混淆
- **问题**：用户以为 GitHub MCP 上传的代码就是 Release
- **原因**：不了解 Commits 和 Releases 的区别
- **解决**：
  - Commits = 代码提交（自动记录）
  - Releases = 正式版本发布（需要手动创建）

### 5. 作者名混淆
- **问题**：README.md 作者名被改为 "Evolution Team"，用户要求保留 "lemen"
- **解决**：修正回 `lemen`

## 解决方案

### 文件上传最佳实践
1. **小项目**（<20 文件）：用 GitHub MCP 逐个上传
2. **大项目**：用 git 命令行 + 代理推送
3. **自动化**：配置 GitHub Actions 自动 Release

### 敏感信息检查
- 上传前用 `grep` 搜索敏感关键词
- 检查本地路径、Token、Webhook、人员 ID
- 使用模板文件代替实际数据
