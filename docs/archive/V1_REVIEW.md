## 1. V1 架构

### 1.1 使用的技术

- **Slash Command**：`.claude/commands/evolution.md`
- **项目级存储**：`evolution-manual/knowledge-base/`
- **索引 + 详情文件**：`kb-index.md` + 8 个详情文件

### 1.2 设计初衷

- 让 AI 记住关键信息
- 让人类在协作中成长
- 保持人机对齐

## 2. 发现的问题

### 2.1 核心问题

| 问题 | 说明 | 根本原因 |
|------|------|---------|
| **AI 不知道知识库存在** | 只有用户输入 `/evolution` 时才加载 | Slash Command 只在触发时加载 |
| **无法自我进化** | AI 不能主动参考历史知识 | 没有渐进式披露机制 |
| **全量读取指令** | 命令指示 AI 读取整个目录 | 指令设计不当 |
| **路径硬编码** | 命令文件写死项目路径 | 不可移植 |

### 2.2 上下文消耗

| 场景 | 消耗 |
|------|------|
| **启动时** | 0 tokens（Slash Command 不加载） |
| **触发时** | ~1000 tokens（全量读取） |
| **总计** | ~1000 tokens |

## 3. 关键发现

### 3.1 Skill 系统的发现

通过官方文档研究，发现 Claude Code 的 Skill 系统支持：

```
启动时：加载 frontmatter 描述（~1 行）
    ↓
每轮对话：AI 看到描述，判断是否需要
    ↓
按需加载：完整内容只在需要时加载
```

### 3.2 渐进式披露的价值

| 特性 | Slash Command | Skill |
|------|--------------|-------|
| **启动时加载** | ❌ 不加载 | ✅ 加载描述 |
| **AI 是否知道** | ❌ 不知道 | ✅ 知道 |
| **自动触发** |  不支持 | ✅ 支持 |
| **上下文消耗** | 0 或 全量 | 极小 或 按需 |

## 4. 经验教训

### 4.1 技术层面

| 教训 | 说明 |
|------|------|
| **使用官方 Skill 系统** | 不要自己发明轮子 |
| **渐进式披露** | 按需加载，控制上下文消耗 |
| **frontmatter 设计** | 清晰描述用途和触发条件 |
| **读取策略** | 明确指令"先读索引，按需读取" |

### 4.2 设计层面

| 教训 | 说明 |
|------|------|
| **AI 需要"知道"才能"进化"** | 必须让 AI 知道知识库存在 |
| **索引的重要性** | 引导 AI 按需读取，避免全量加载 |
| **向后兼容** | 保留 Slash Command 作为备选 |

---

## 5. V2 改进方向

### 5.1 核心改进

1. **迁移到 Skill 系统**
   - 使用 frontmatter
   - 支持渐进式披露
   - 允许自动触发

2. **优化读取策略**
   - 明确"先读索引"
   - 按需读取详情
   - 节省 66% 上下文

3. **保留向后兼容**
   - 保留 Slash Command
   - 命令指向 Skill

### 5.2 预期收益

| 指标 | V1 | V2 | 改进 |
|------|-----|-----|------|
| **启动消耗** | 0 | ~20 tokens | +20 tokens（但 AI 知道了） |
| **触发消耗** | ~1000 | ~320 tokens | **-68%** |
| **自动触发** | ❌ | ✅ | **质的飞跃** |
| **自我进化** | ❌ | ✅ | **核心目标达成** |
