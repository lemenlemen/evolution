## 执行命令设计

### 初始化命令

```bash
/evolution-init
```

**设计考虑**：
- 首次安装后使用
- 分析全部历史对话
- 建立初始知识库
- 所有条目标记为 `[D]` (draft)

**执行流程**：
```
用户输入 /evolution-init
    ↓
主 agent 触发 sub agent
    ↓
Sub agent 在后台：
  1. 分析全部历史对话
  2. 提取所有关键事实
  3. 记录所有踩坑记录
  4. 生成初始知识库
  5. 标记所有条目为 [D]
    ↓
返回摘要给主 agent
    ↓
主 agent 显示摘要
```

## 对话导出机制设计

### 导出方式：evolution-export.py

**设计考虑**：
- 通过脚本导出全部历史对话，防止采样
- 支持全量导出（`--mode full`）与增量导出（`--mode incremental`）
- 跨进程文件锁保证并发安全
- 主 session 几乎不被污染

**适用场景**：
- 初始化（`/evolution-init`）：全量导出全部历史对话
- 增量同步（`/evolution`）：仅导出新增对话

**执行**：
```bash
# 全量导出（初始化）
python .claude/skills/evolution/evolution-export.py --mode full

# 增量导出（同步）
python .claude/skills/evolution/evolution-export.py --mode incremental
```

## Sub Agent 执行设计

### 为什么用 Sub Agent？

**核心原则**：
> 尽量减少对主会话的污染

**好处**：
1. ✅ 主 session 几乎不被污染
2. ✅ 主 session 保持流畅
3. ✅ 知识库操作在后台完成
4. ✅ 用户体验更好

### 职责分工

**主 agent**：
- 接收用户命令
- 触发 sub agent
- 显示 sub agent 返回的摘要
- **不直接操作知识库**

**Sub agent**：
- 读取对话历史
- 提取知识
- 写入知识库
- 返回摘要

## 写入审核机制设计

### 状态标记

| 状态 | 标记 | 含义 |
|------|------|------|
| draft | `[D]` | AI 提取，未经用户验证 |
| verified | `[V]` | 用户明确确认或工具验证 |
| deprecated | `[X]` | 已废弃或已证实错误 |

### 设计考虑

**为什么默认标记为 `[D]`？**
- 确保所有知识都经过人工审核
- 防止 AI 错误信息污染知识库
- 用户有最终控制权

**为什么需要 `[V]` 状态？**
- 用户确认的知识可以直接使用
- 提高使用效率
- 建立信任机制

## 渐进式读取设计

### 为什么需要渐进式读取？

**问题**：
- 知识库有 8 个文件
- 全量加载会污染上下文
- 浪费 token

**解决方案**：
1. 先读索引（`kb-index.md`）
2. 判断需要什么
3. 只读相关文件（1-2 个）

**好处**：
- ✅ 减少上下文污染
- ✅ 节省 token
- ✅ 提高效率
